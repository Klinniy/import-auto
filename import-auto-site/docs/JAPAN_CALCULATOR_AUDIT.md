# Технический аудит японского калькулятора MosaicAuto

Дата статического аудита: 2026-07-14. Обновление после живой staging-проверки: 2026-07-14.

## Итоговый статус

**Частично подтверждено.**

Статически подтверждено, что серверный маршрут `/api/calculator/japan` не использует локальную приблизительную формулу для таможни: он дважды вызывает внешний Calcos API и затем собирает итог из ответа API, курсов валют и фиксированных расходов. Живая staging-проверка подтвердила доступность Calcos API для 12 запросов, но выявила, что production route не разбирает реальные курсы из тега `<currency>` и поэтому использует fallback-курс USD для части расчёта. Корректность бизнес-сравнения итоговой стоимости сайта с `<sum>` API остаётся неподтверждённой, потому что не установлено, одинаковый ли набор расходов входит в эти суммы.

## Схема текущей работы

1. Пользователь открывает `/calculator/japan`, страница рендерит общий компонент `ImportCalculator` с `market="japan"`.
2. Форма отправляет `POST /api/calculator/japan` из браузера.
3. Клиент умножает введённую пользователем стоимость на 1000 перед отправкой: поле в UI подписано как JPY, но фактически значение формы трактуется как тысячи JPY.
4. Сервер валидирует и нормализует входные поля: стоимость аукциона, год, объём двигателя, мощность, тип топлива и признак `passing`.
5. Сервер загружает курсы ЦБ РФ через `https://www.cbr.ru/scripts/XML_daily.asp`; при ошибке использует fallback-курсы.
6. Сервер формирует два GET-запроса к внешнему API из `CALCOS_DUTY_API_URL`: для физического лица (`tax_mode=2`) и юридического лица (`tax_mode=1`).
7. Сервер ожидает XML-подобный ответ и извлекает теги `sum`, `fiz`, `jur`, `fiz_info`, `jur_info`, `tax_mode`, `usd`, `eur`, `jpy`. В живом ответе курсы пришли не в отдельных тегах, а в строке `<currency>`.
8. Сервер собирает два результата: расходы в Японии, расходы в России, итог в RUB и сырой ответ API.
9. Клиент нормализует JSON-ответ сервера и отображает две вкладки: физическое и юридическое лицо.

## Контракт запроса пользователя на сервер

`POST /api/calculator/japan`, `Content-Type: application/json`.

| Поле | Источник формы | Единицы/смысл | Серверное использование |
| --- | --- | --- | --- |
| `aucPrice` | `price * 1000` | JPY | Основная цена авто для расчёта и для внешнего API. |
| `auctionPrice`, `priceJpy` | `price * 1000` | JPY | Дублирующие поля; текущий сервер берёт `aucPrice`. |
| `price`, `cost` | исходное поле формы | тысячи JPY в текущей UI-логике | `price`/`cost` используются только как fallback, если нет `aucPrice`; это риск рассинхронизации. |
| `year` | год выпуска | год | Передаётся во внешний API как `year`. |
| `volume`, `engineVolume`, `engine` | объём двигателя | см³ | Передаётся во внешний API как `volume`. |
| `power`, `hp` | мощность ДВС | л.с. | Передаётся во внешний API как `power`. |
| `electricPower`, `electroPower` | мощность электро | л.с. | Сейчас сервером японского маршрута не используется. |
| `fuel` / `fuelCode` | выбранный тип топлива | код Calcos | Сервер читает `fuel`; коды: 1 дизель, 2 бензин, 3 электро, 4 гибрид, 5 дизельный гибрид. |
| `isProhChecked` | чекбокс «моложе 3 лет» | 0/1 | Передаётся во внешний API как `passing`. Название признака неоднозначно и требует проверки с владельцем API. |
| `dvs30` | чекбокс ДВС/ЭД | boolean | Сейчас сервером японского маршрута не используется. |

## Контракт запроса во внешний API

HTTP-метод: **GET**.

URL: базовый URL из `CALCOS_DUTY_API_URL`. В логах диагностики отображается только безопасная форма вида `https://calcos.example/api/[redacted]`; реальный путь, ключи и query-параметры не сохраняются.

Query-параметры, которые добавляет сервер:

| Параметр | Значение | Единицы/смысл |
| --- | --- | --- |
| `verbose` | `1` | Запрос подробного ответа. |
| `price` | `Math.round(aucPrice)` | По текущей серверной логике это JPY, несмотря на внутреннее имя `priceRub`. |
| `sheet1` | env/body, default `65000` | JPY, расходы по Японии/аукционный лист в текущей модели. |
| `year` | год выпуска | год. |
| `passing` | `0` или `1` | Признак из чекбокса «моложе 3 лет». |
| `power` | мощность | л.с. |
| `volume` | объём двигателя | см³. |
| `fuel` | `1..5` | 1 дизель, 2 бензин, 3 электро, 4 бензиновый гибрид, 5 дизельный гибрид. |
| `tax_mode` | `2` или `1` | 2 — физическое лицо, 1 — юридическое лицо. |
| `or_change_tax_mode_to_0` | `1` | Разрешает API изменить режим налогообложения; фактический режим читается из `tax_mode` ответа. |

## Ожидаемый и фактический формат ответа внешнего API

Маршрут сейчас ожидает XML/текст с тегами:

| Тег | Использование |
| --- | --- |
| `sum` | Парсится диагностикой как `apiSumRub`; production route сейчас не использует его в итоговой сумме. |
| `fiz` | Общий таможенный платёж для физического лица, используется как fallback для пошлины. |
| `jur` | Общий таможенный платёж для юридического лица, используется как fallback для пошлины. |
| `fiz_info` | Строка детализации. Первое число трактуется как пошлина в USD-like единицах, второе число — как утильсбор в USD-like единицах. |
| `jur_info` | Аналогично для юридического лица. |
| `tax_mode` | Сохраняется в ответе, но не влияет на сборку итоговой суммы. |
| `usd`, `eur`, `jpy` | Legacy-теги курсов, которые ищет production route. В живом staging-ответе они отсутствовали. |
| `currency` | Фактическая строка курсов в staging: `USDRUB_system:...;EURRUB_system:...;JPYRUB_system:...;`. Обновлённая диагностика разбирает её отдельно. |

### Курсы валют

Живая staging-проверка показала, что Calcos возвращает курсы внутри `<currency>`, например в формате `USDRUB_system:76.6213;EURRUB_system:87.5781;JPYRUB_system:0.472679;...`. Текущий production route ищет отдельные теги `<usd>`, `<eur>`, `<jpy>`, поэтому для USD/EUR в route-equivalent расчёте включается fallback, а не фактический курс Calcos. Обновлённая диагностика выводит два расчёта: точное воспроизведение текущего route и альтернативный расчёт с курсами из `<currency>`.

### Валюта таможенного платежа

По текущему коду таможенный платёж трактуется как сумма в USD-like единицах: `fiz`/`jur` или числа из `fiz_info`/`jur_info` умножаются на USD/RUB. Это ключевая гипотеза, которую нужно подтвердить документацией Calcos или владельцем API.

## Таблица компонентов итоговой суммы

| Компонент | Источник | Валюта источника | Перевод в RUB в production route | Показывается пользователю |
| --- | --- | --- | --- | --- |
| Стоимость авто на аукционе | `aucPrice` из формы | JPY | `aucPrice * currency.jpyPerOne` по ЦБ или fallback ЦБ | Да, в «Расходы в Японии». |
| Расходы по Японии / `sheet1` | body/env `CALCOS_JAPAN_SHEET1`, default 65000 | JPY | `sheet1 * currency.jpyPerOne` по ЦБ или fallback ЦБ | Да. |
| Фрахт до Владивостока | body/env `CALCOS_JAPAN_FREIGHT_USD`, default 350 | USD | `freightUsd * calcos.rates.usdRub`; на staging из-за отсутствия `<usd>` это fallback 88 | Да. |
| Таможенная пошлина | первое число из `*_info` или весь `fiz`/`jur` fallback | USD-like | `value * calcos.rates.usdRub`; на staging из-за отсутствия `<usd>` это fallback 88 | Да. |
| Утилизационный сбор | второе число из `*_info` | USD-like | `value * calcos.rates.usdRub`; на staging из-за отсутствия `<usd>` это fallback 88 | Да. |
| Склад временного хранения | body/env `CALCOS_JAPAN_STORAGE_RUB`, default 6000 | RUB | без конвертации | Да. |
| Таможенное оформление / брокер | body/env `CALCOS_JAPAN_BROKER_RUB`, default 6000 | RUB | без конвертации | Да. |
| ЭРА-ГЛОНАСС / оформление | body/env `CALCOS_JAPAN_GLONASS_RUB`, default 50000 | RUB | без конвертации | Да. |
| СБКТС/ЭПТС | отдельного компонента нет | — | — | Не учитывается отдельной строкой. Может быть неявно включён в ГЛОНАСС/оформление только организационно, кодом это не подтверждено. |

Формула текущего `routeEquivalentTotalRub`:

```text
routeEquivalentTotalRub = aucRub
  + sheet1Rub
  + freightRub
  + customsDutyRub
  + utilFeeRub
  + storageRub
  + brokerRub
  + glonassRub
```

`componentsIndependentTotalRub` в диагностике считается отдельным суммированием всех компонент. Если `diffRouteVsComponentsRub !== 0`, это техническая ошибка диагностики или расхождение с route-логикой. Если `diffRouteVsApiRub !== 0`, это пока только WARNING, потому что не подтверждено, что `<sum>` API включает тот же набор расходов, что и сайт.

## Результаты живого staging-теста

- Внешний API стабильно вернул HTTP 200 для 12 запросов: 6 сценариев × 2 режима (`tax_mode=2` и `tax_mode=1`).
- В каждом ответе присутствовала строка `<currency>` с курсами `USDRUB_system`, `EURRUB_system`, `JPYRUB_system`.
- Текущий production route не использует эти курсы из-за неправильного ожидания отдельных тегов `<usd>`, `<eur>`, `<jpy>`.
- Поэтому route-equivalent расчёт сайта использовал fallback USD/RUB для фрахта, пошлины и утилизационного сбора, а альтернативный расчёт диагностики с курсами Calcos показывает влияние этого fallback.
- Несовпадение `routeEquivalentTotalRub` или `componentsIndependentTotalRub` с `apiSumRub` не доказывает само по себе ошибку итоговой стоимости сайта: `<sum>` может включать иной набор расходов или только часть расчёта. Это требует подтверждения контракта Calcos.

Точные расхождения на staging нужно смотреть в выводе обновлённой команды: она печатает `apiSumRub`, `routeEquivalentTotalRub`, `componentsIndependentTotalRub`, `diffRouteVsComponentsRub`, `diffRouteVsApiRub`, `diffComponentsVsApiRub` и процентное расхождение с API для каждого сценария и режима.

## Поведение при ошибках

- Если `CALCOS_DUTY_API_URL` не задан, внешний запрос не выполняется, диагностика завершается с кодом `2` и сообщает, какой env отсутствует.
- Если внешний API возвращает не-2xx, диагностика считает это технической ошибкой и завершается с ненулевым кодом.
- Если `<sum>` отсутствует или не парсится, диагностика завершается с ненулевым кодом.
- Если строка `<currency>` не парсится в USD/RUB, EUR/RUB и JPY/RUB за 1 JPY, диагностика завершается с ненулевым кодом.
- Если сумма компонентов не совпадает с route-equivalent итогом, диагностика завершается с ненулевым кодом.
- Если route/components расходятся с `<sum>`, диагностика печатает WARNING, но не считает это техническим падением автоматически.

## Найденные риски и ошибки

1. **Production route не разбирает фактический `<currency>` Calcos.** На staging курсы пришли в строке `USDRUB_system:...;EURRUB_system:...;JPYRUB_system:...`, а текущий route ищет отдельные теги `<usd>`, `<eur>`, `<jpy>`.
2. **Не подтверждена единица `price` для Calcos.** Сервер передаёт `aucPrice` как `price`, а внутреннее имя параметра `priceRub` вводит в заблуждение. Документально требуется подтвердить, что API ждёт именно JPY, а не RUB.
3. **UI умножает цену на 1000 при подписи JPY.** Пользователь видит «Стоимость авто на аукционе, JPY», но значение `1200` отправляется как `1 200 000 JPY`. Это может быть корректной бизнес-договорённостью «тыс. JPY», но подпись формы её не отражает.
4. **`passing` связан с чекбоксом «моложе 3 лет».** Требуется подтвердить, что внешний API ожидает именно такой флаг, а не признак проходного года/проходной пошлины.
5. **Разбор `fiz_info`/`jur_info` хрупкий.** Код берёт первые два числа из текстовой строки. Если API изменит порядок или добавит дополнительные числа до пошлины/утильсбора, итог станет неверным.
6. **Нет серверной проверки успешного разбора таможни.** 2xx-ответ без ожидаемых тегов приведёт к нулевым платежам вместо ошибки.
7. **СБКТС/ЭПТС не выделены отдельной строкой.** Если бизнес требует учитывать их отдельно, текущий расчёт этого не делает.
8. **Курсы JPY берутся из ЦБ, а USD для фрахта/таможни — из Calcos legacy-тегов или fallback.** В живом ответе legacy-тегов нет, поэтому диагностика фиксирует использование fallback USD/RUB.
9. **`electricPower` и `dvs30` сейчас не доходят до внешнего API.** Если Calcos поддерживает эти параметры, текущий маршрут их игнорирует.

## Диагностический скрипт

Добавлен ручной серверный скрипт:

```bash
npm run audit:calculator:japan
```

Скрипт:

- читает настройки из env;
- не печатает секреты, скрывает чувствительную часть пути URL и query-параметры;
- выполняет 6 тестовых сценариев: бензин до 3 лет, бензин 3–5 лет, дизель старше 5 лет, электро, бензиновый гибрид, дизельный гибрид;
- для каждого сценария делает два GET-запроса к Calcos: `tax_mode=2` и `tax_mode=1`;
- печатает входные параметры, HTTP-статус, безопасный фрагмент ответа, распознанную таможню, источники курсов, компоненты RUB, `apiSumRub`, `routeEquivalentTotalRub`, `componentsIndependentTotalRub`, diff-поля и процентное расхождение с API;
- отдельно показывает альтернативный расчёт с курсами из `<currency>` Calcos;
- завершается с ненулевым кодом, если нет обязательного env, API вернул ошибку, `<sum>` или курсы не распознаны, либо сумма компонентов расходится с route-equivalent итогом.

Команда:

```bash

```

## Что нельзя подтвердить без контракта Calcos

- Реальный смысл `<sum>`: включает ли он только таможенные платежи, всю стоимость до города доставки или другой набор расходов.
- Валюту и семантику полей `fiz`, `jur`, `fiz_info`, `jur_info`.
- Правильность `tax_mode=1/2` для юридического/физического лица в текущей интеграции.
- Правильность признака `passing` и влияния возраста автомобиля.
- Нужны ли внешнему API параметры `electricPower` и `dvs30`.
- Стабильность порядка чисел в `fiz_info`/`jur_info`.

## Команды для повторной проверки на staging

На staging с настроенными env выполнить:

```bash
cd import-auto-site
npm run test:audit:calculator:japan
npm run audit:calculator:japan
npm run build
```

Если диагностика завершится с кодом `0`, она подтверждает только то, что текущая сборка маршрута, текущий env и текущий живой формат ответа API согласованы по сумме компонентов и route-equivalent логике. WARNING по сравнению с `<sum>` нужно анализировать отдельно вместе с контрактом Calcos.
