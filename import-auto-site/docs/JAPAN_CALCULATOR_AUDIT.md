# Технический аудит японского калькулятора MosaicAuto

Дата статического аудита: 2026-07-14.

## Итоговый статус

**Частично подтверждено.**

Статически подтверждено, что серверный маршрут `/api/calculator/japan` не использует локальную приблизительную формулу для таможни: он дважды вызывает внешний Calcos API и затем собирает итог из ответа API, курсов валют и фиксированных расходов. Корректность живого контракта Calcos, валюты полей `fiz`/`jur` и устойчивость разбора `fiz_info`/`jur_info` невозможно полностью подтвердить без реальных `CALCOS_*` env и живого ответа API.

## Схема текущей работы

1. Пользователь открывает `/calculator/japan`, страница рендерит общий компонент `ImportCalculator` с `market="japan"`.
2. Форма отправляет `POST /api/calculator/japan` из браузера.
3. Клиент умножает введённую пользователем стоимость на 1000 перед отправкой: поле в UI подписано как JPY, но фактически значение формы трактуется как тысячи JPY.
4. Сервер валидирует и нормализует входные поля: стоимость аукциона, год, объём двигателя, мощность, тип топлива и признак `passing`.
5. Сервер загружает курсы ЦБ РФ через `https://www.cbr.ru/scripts/XML_daily.asp`; при ошибке использует fallback-курсы.
6. Сервер формирует два GET-запроса к внешнему API из `CALCOS_DUTY_API_URL`: для физического лица (`tax_mode=2`) и юридического лица (`tax_mode=1`).
7. Сервер ожидает XML-подобный ответ и извлекает теги `sum`, `fiz`, `jur`, `fiz_info`, `jur_info`, `tax_mode`, `usd`, `eur`, `jpy`.
8. Сервер собирает два результата: расходы в Японии, расходы в России, итог в RUB и сырой ответ API.
9. Клиент нормализует JSON-ответ сервера и отображает две вкладки: физическое и юридическое лицо.

## Контракт запроса пользователя на сервер

`POST /api/calculator/japan`, `Content-Type: application/json`.

| Поле | Источник формы | Единицы/смысл | Серверное использование |
| --- | --- | --- | --- |
| `aucPrice` | `price * 1000` | JPY | Основная цена авто для расчёта и для внешнего API. |
| `auctionPrice`, `priceJpy` | `price * 1000` | JPY | Дублирующие поля; текущий сервер берёт `aucPrice`. |
| `price`, `cost` | исходное поле формы | тысячи JPY в текущей UI-логике | `price`/`cost` используются только как fallback, если нет `aucPrice`; это риск рассинхронизации. |
| `year` | год выпуска | год | Передаётся во внешний API как `year`. |
| `volume`, `engineVolume`, `engine` | объём двигателя | см³ | Передаётся во внешний API как `volume`. |
| `power`, `hp` | мощность ДВС | л.с. | Передаётся во внешний API как `power`. |
| `electricPower`, `electroPower` | мощность электро | л.с. | Сейчас сервером японского маршрута не используется. |
| `fuel` / `fuelCode` | выбранный тип топлива | код Calcos | Сервер читает `fuel`; коды: 1 дизель, 2 бензин, 3 электро, 4 гибрид, 5 дизельный гибрид. |
| `isProhChecked` | чекбокс «моложе 3 лет» | 0/1 | Передаётся во внешний API как `passing`. Название признака неоднозначно и требует проверки с владельцем API. |
| `dvs30` | чекбокс ДВС/ЭД | boolean | Сейчас сервером японского маршрута не используется. |

## Контракт запроса во внешний API

HTTP-метод: **GET**.

URL: базовый URL из `CALCOS_DUTY_API_URL`. Скрипт диагностики и документация не должны печатать полный URL с чувствительными query-параметрами.

Query-параметры, которые добавляет сервер:

| Параметр | Значение | Единицы/смысл |
| --- | --- | --- |
| `verbose` | `1` | Запрос подробного ответа. |
| `price` | `Math.round(aucPrice)` | По текущей серверной логике это JPY, несмотря на внутреннее имя `priceRub`. |
| `sheet1` | env/body, default `65000` | JPY, расходы по Японии/аукционный лист в текущей модели. |
| `year` | год выпуска | год. |
| `passing` | `0` или `1` | Признак из чекбокса «моложе 3 лет». |
| `power` | мощность | л.с. |
| `volume` | объём двигателя | см³. |
| `fuel` | `1..5` | 1 дизель, 2 бензин, 3 электро, 4 бензиновый гибрид, 5 дизельный гибрид. |
| `tax_mode` | `2` или `1` | 2 — физическое лицо, 1 — юридическое лицо. |
| `or_change_tax_mode_to_0` | `1` | Разрешает API изменить режим налогообложения; фактический режим читается из `tax_mode` ответа. |

## Ожидаемый формат ответа внешнего API

Маршрут ожидает XML/текст с тегами:

| Тег | Использование |
| --- | --- |
| `sum` | Парсится, но сейчас не участвует в итоговой сумме. |
| `fiz` | Общий таможенный платёж для физического лица, используется как fallback. |
| `jur` | Общий таможенный платёж для юридического лица, используется как fallback. |
| `fiz_info` | Строка детализации. Первое число трактуется как пошлина в USD-like единицах, второе число — как утильсбор в USD-like единицах. |
| `jur_info` | Аналогично для юридического лица. |
| `tax_mode` | Сохраняется в ответе, но не влияет на сборку итоговой суммы. |
| `usd` | Курс USD/RUB от API, приоритетнее курса ЦБ для пересчёта таможни и фрахта. |
| `eur` | Парсится и возвращается в `raw`, в расчёте не участвует. |
| `jpy` | Парсится как «100 JPY в RUB» в данных API, но для цены авто сервер использует курс ЦБ `jpyPerOne`. |

### Валюта таможенного платежа

По текущему коду таможенный платёж трактуется как сумма в USD-like единицах: `fiz`/`jur` или числа из `fiz_info`/`jur_info` умножаются на `usd` из ответа Calcos. Это ключевая гипотеза, которую нужно подтвердить живым API и документацией Calcos.

## Таблица компонентов итоговой суммы

| Компонент | Источник | Валюта источника | Перевод в RUB | Показывается пользователю |
| --- | --- | --- | --- | --- |
| Стоимость авто на аукционе | `aucPrice` из формы | JPY | `aucPrice * currency.jpyPerOne` по ЦБ | Да, в «Расходы в Японии». |
| Расходы по Японии / `sheet1` | body/env `CALCOS_JAPAN_SHEET1`, default 65000 | JPY | `sheet1 * currency.jpyPerOne` по ЦБ | Да. |
| Фрахт до Владивостока | body/env `CALCOS_JAPAN_FREIGHT_USD`, default 350 | USD | `freightUsd * calcos.usd` | Да. |
| Таможенная пошлина | первое число из `*_info` или весь `fiz`/`jur` fallback | USD-like | `value * calcos.usd` | Да. |
| Утилизационный сбор | второе число из `*_info` | USD-like | `value * calcos.usd` | Да. |
| Склад временного хранения | body/env `CALCOS_JAPAN_STORAGE_RUB`, default 6000 | RUB | без конвертации | Да. |
| Таможенное оформление / брокер | body/env `CALCOS_JAPAN_BROKER_RUB`, default 6000 | RUB | без конвертации | Да. |
| ЭРА-ГЛОНАСС / оформление | body/env `CALCOS_JAPAN_GLONASS_RUB`, default 50000 | RUB | без конвертации | Да. |
| СБКТС/ЭПТС | отдельного компонента нет | — | — | Не учитывается отдельной строкой. Может быть неявно включён в ГЛОНАСС/оформление только организационно, кодом это не подтверждено. |

Формула текущего `totalRub`:

```text
totalRub = aucRub
  + sheet1Rub
  + freightRub
  + customsDutyRub
  + utilFeeRub
  + storageRub
  + brokerRub
  + glonassRub
```

В статическом коде не найдено двойного прибавления одной и той же строки: сумма результата равна сумме реально показываемых компонентов в двух секциях.

## Поведение при ошибках

- Если `CALCOS_DUTY_API_URL` не задан, внешний запрос не выполняется, маршрут возвращает HTTP 502 с JSON `{ ok: false, error: "CALCOS_DUTY_API_URL is empty" }`.
- Если внешний API возвращает не-2xx, сервер читает первые 200 символов ответа и возвращает HTTP 502 с текстом ошибки.
- Если формат XML неожиданный, числовые поля парсятся как `0`. Специальной валидации «таможня не распознана» в маршруте нет, поэтому пользователь может получить расчёт с нулевой таможней, если внешний API вернул 2xx, но без ожидаемых тегов.
- Если ЦБ недоступен, сервер использует fallback-курсы: USD 88, EUR 95, 100 JPY 48 RUB.

## Найденные риски и ошибки

1. **Не подтверждена единица `price` для Calcos.** Сервер передаёт `aucPrice` как `price`, а внутреннее имя параметра `priceRub` вводит в заблуждение. Документально требуется подтвердить, что API ждёт именно JPY, а не RUB.
2. **UI умножает цену на 1000 при подписи JPY.** Пользователь видит «Стоимость авто на аукционе, JPY», но значение `1200` отправляется как `1 200 000 JPY`. Это может быть корректной бизнес-договорённостью «тыс. JPY», но подпись формы её не отражает.
3. **`passing` связан с чекбоксом «моложе 3 лет».** Требуется подтвердить, что внешний API ожидает именно такой флаг, а не признак проходного года/проходной пошлины.
4. **Разбор `fiz_info`/`jur_info` хрупкий.** Код берёт первые два числа из текстовой строки. Если API изменит порядок или добавит дополнительные числа до пошлины/утильсбора, итог станет неверным.
5. **Нет серверной проверки успешного разбора таможни.** 2xx-ответ без ожидаемых тегов приведёт к нулевым платежам вместо ошибки.
6. **СБКТС/ЭПТС не выделены отдельной строкой.** Если бизнес требует учитывать их отдельно, текущий расчёт этого не делает.
7. **Курсы JPY берутся из ЦБ, а USD для фрахта/таможни — из Calcos.** Это может быть намеренно, но источник курсов смешанный.
8. **`electricPower` и `dvs30` сейчас не доходят до внешнего API.** Если Calcos поддерживает эти параметры, текущий маршрут их игнорирует.

## Диагностический скрипт

Добавлен ручной серверный скрипт:

```bash
npm run audit:calculator:japan
```

Скрипт:

- читает настройки из env;
- не печатает секреты и редактирует query-параметры URL;
- выполняет 6 тестовых сценариев: бензин до 3 лет, бензин 3–5 лет, дизель старше 5 лет, электро, бензиновый гибрид, дизельный гибрид;
- для каждого сценария делает два GET-запроса к Calcos: `tax_mode=2` и `tax_mode=1`;
- печатает входные параметры, HTTP-статус, безопасный фрагмент ответа, распознанную таможню, компоненты RUB, заявленный и независимо пересчитанный итог;
- завершается с ненулевым кодом, если нет обязательного env, API не вернул корректный платёж или сумма компонентов расходится.

## Что нельзя подтвердить без реального env и живого API

- Реальный базовый URL `CALCOS_DUTY_API_URL` и наличие обязательных параметров авторизации.
- Валюту и семантику полей `fiz`, `jur`, `fiz_info`, `jur_info`.
- Правильность `tax_mode=1/2` для юридического/физического лица в текущей интеграции.
- Правильность признака `passing` и влияния возраста автомобиля.
- Нужны ли внешнему API параметры `electricPower` и `dvs30`.
- Стабильность структуры XML на разных типах топлива и разных возрастах.
- Совпадение расчёта на staging с production env.

## Команда для проверки на staging

На staging с настроенными env выполнить:

```bash
cd import-auto-site
npm run audit:calculator:japan
npm run build
```

Если диагностика завершится с кодом `0`, она подтверждает только то, что текущая сборка маршрута, текущий env и текущий живой формат ответа API согласованы по сумме компонентов. Она не заменяет бизнес-проверку тарифов таможни и документации внешнего API.
