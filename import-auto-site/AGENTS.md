# MosaicAuto / Import Auto — правила работы Codex

## Проект

- Основное приложение находится в папке `import-auto-site`.
- Стек: Next.js App Router, React, TypeScript, Prisma и PostgreSQL.
- Основной production-домен: mosaicauto.ru.
- Общение с владельцем проекта вести на русском языке.
- Имена функций, переменных, типов и файлов писать на английском языке.

## Структура

- Страницы и route handlers находятся в `app`.
- UI-компоненты находятся в `components`.
- Серверная бизнес-логика и адаптеры находятся в `lib`.
- Prisma-схема находится в `prisma`.
- Статические файлы находятся в `public`.
- Не размещать серверные секреты и бизнес-логику в клиентских компонентах.

## Команды

Все команды выполнять из папки `import-auto-site`.

- Установка зависимостей: `npm ci`
- Локальный запуск: `npm run dev`
- Production-сборка: `npm run build`
- Проверка lint: `npm run lint`

## Проверка изменений

- Перед завершением любой задачи с изменением кода запускать `npm run build`.
- Если менялся только Markdown или документация, сборку можно не запускать, но нужно проверить `git diff`.
- Не утверждать, что задача выполнена, если обязательная проверка завершилась ошибкой.
- После изменений API перечислять endpoints для ручной проверки.
- После изменений UI перечислять страницы для визуальной проверки.
- В итоговом ответе указывать изменённые файлы и выполненные команды.

## Git

- Не вносить изменения напрямую в production-сервер.
- Не выполнять push, merge или deployment без явного разрешения владельца.
- Одна задача должна содержать одно логически цельное изменение.
- Не смешивать исправление ошибки, рефакторинг и изменение дизайна без необходимости.
- Перед завершением показывать `git status --short` и итоговый diff.
- Не использовать force push.
- Не изменять историю ветки `main`.

## Production

- Не подключаться к production-серверу по SSH.
- Не выполнять `pm2 restart`, deployment, миграции или изменение production-БД.
- Не изменять production `.env`.
- Не запускать опасные Prisma-команды против production-БД.
- Не удалять и не деактивировать данные каталога при пустом ответе внешнего API.

## Секреты

- Никогда не читать, не выводить и не коммитить значения секретов.
- Не коммитить `.env`, `.env.local`, `.env.production`, API-ключи, DATABASE_URL, JWT_SECRET и пароли.
- Не помещать закрытые ключи в переменные `NEXT_PUBLIC_*`.
- Не выводить секреты, их длину или содержимое в публичных debug-ответах.
- В логах маскировать ключи и чувствительные URL.

## Внешние API

- AVTO.JP / AJES и другие внешние API вызываются только серверным кодом.
- Нельзя принимать произвольный SQL от пользователя.
- Нельзя создавать публичный endpoint вида `/api/proxy?sql=...`.
- Новые SQL-фильтры должны использовать существующие функции нормализации и экранирования.
- По возможности ограничивать AJES-запросы только операциями `SELECT`.
- Клиентские компоненты должны обращаться только к локальным API routes сайта.
- При сбое внешнего API сайт должен сохранять последнее рабочее состояние.

## Требования MosaicAuto

- Не возвращать авторизацию, личный кабинет, избранное и связанные кнопки без отдельного запроса.
- Не возвращать блоки «Получить расчёт» и «Комментарии / примечания» без отдельного запроса.
- Сохранять единую шапку сайта.
- Не ломать маршруты Японии, Китая, Кореи, калькуляторов и статистики.
- Не добавлять мок-данные в боевые страницы без явной маркировки.
- Не менять существующий API-контракт без необходимости.
- Не дублировать логику валют, изображений и нормализации, если в проекте уже есть соответствующий модуль.

## Формат итогового отчёта

После выполнения задачи сообщать:

1. Что изменено.
2. Какие файлы затронуты.
3. Какие команды выполнены.
4. Результат сборки или причина, почему она не требовалась.
5. Что проверить вручную.
6. Нужны ли новые переменные окружения, миграции или действия на сервере.
